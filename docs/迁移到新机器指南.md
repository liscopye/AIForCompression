# AIForCompression 迁移到新机器指南

本文说明将当前仓库迁移到另一台 Linux 机器时需要安装和复制的内容。迁移分为三个层级；先确定目标，再决定是否复制约 24 GB checkpoint 和约 1.5 TB 数据。

## 1. 先选择迁移范围

| 目标 | 必须迁移 | 不需要迁移 |
|---|---|---|
| 只查看正式结果 | Git 仓库 | GPU、数据、checkpoint、训练日志 |
| 复现评测 | 仓库、submodule、所用数据、对应 checkpoint、CUDA/Python 环境 | 其他数据集、训练日志、历史备份 |
| 继续训练 | 上述全部、训练集、最终/断点权重；需要时复制 W&B 日志 | 已废弃结果、旧编译产物 |
| 完整归档 | 仓库、全部数据、checkpoint、当前结果、历史备份和需要保留的日志 | 临时文件和可重新生成的 build/cache |

只查看结果时，克隆仓库后直接打开：

```text
unified_results/objective_all_to_all_v1/index.html
```

## 2. 推荐硬件和系统

- Linux x86_64。当前环境为 Linux、Python 3.12.3、CUDA Toolkit 12.9。
- 复现 GPU 模型需要 NVIDIA GPU 和兼容 CUDA 12 的驱动。当前验证环境使用 RTX 5090 32 GB；这不是硬性型号要求，但显存较小可能需要减小 batch 或无法运行部分模型。
- 只阅读报告和处理已有 JSON 不需要 GPU。
- 完整复制 checkpoint 需额外约 24 GB；复制全部当前数据建议至少预留 2 TB。只复现个别数据集时按需复制即可。
- 不要复制旧机器中 `models/**/build` 等编译产物；不同 CUDA、GPU 或编译器环境应重新编译。

建议安装的基础工具（Ubuntu/Debian）：

```bash
sudo apt-get update
sudo apt-get install -y \
  git git-lfs build-essential cmake ninja-build ffmpeg \
  python3 python3-venv python3-dev
git lfs install
```

处理 GRIB、NetCDF 或 HDF5 原始数据时，可能还需要发行版提供的 ecCodes、NetCDF 和 HDF5 开发库。具体包名随发行版变化。

## 3. 克隆代码和 submodule

为了尽量避免修改硬编码路径，推荐继续使用以下布局：

```text
/workspace/AIForCompression   # 仓库
/workspace/Data               # 数据
```

在新机器执行：

```bash
mkdir -p /workspace
cd /workspace
git clone --recurse-submodules https://github.com/liscopye/AIForCompression.git
cd AIForCompression
git submodule update --init --recursive
```

仓库包含 GraphComp、Visemz、cuSZ-Hi、SZ3、PRISM 和 Aurora 等 submodule。某些 submodule 并非 objective-v1 正式评测所必需，但完整克隆可减少以后补环境的工作。

检查代码是否完整：

```bash
git submodule status --recursive
git status --short
```

## 4. 创建 Python/CUDA 环境

推荐先使用 Python 3.12 创建独立环境：

```bash
cd /workspace/AIForCompression
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

`requirements.txt` 固定了当前主环境的关键版本，包括 PyTorch 2.9、CUDA 12 Python 库、CuPy、Torch Geometric、NumPy、SciPy、xarray、h5netcdf、cfgrib、LPIPS 和绘图库。

少数原始数据或训练入口可能按需使用未纳入主依赖的包，例如 `netCDF4`、OpenCV 或 W&B；遇到明确的 import 错误时再为对应任务安装，不必为只查看结果提前安装。

确认驱动、编译器和 Python GPU 环境：

```bash
nvidia-smi
nvcc --version
python - <<'PY'
import torch
import cupy
import numpy
import xarray

print("torch:", torch.__version__)
print("CUDA available:", torch.cuda.is_available())
print("torch CUDA:", torch.version.cuda)
print("GPU:", torch.cuda.get_device_name(0) if torch.cuda.is_available() else "none")
print("cupy:", cupy.__version__)
PY
```

若使用 DCVC/DCMVC、cuSZ-Hi 或 nvJPEG 等包含 CUDA/C++ 扩展的方法，应在新机器按各模型 README 重新构建。DCVC 的仓库辅助入口为：

```bash
cd models/DCVC/src/layers/extensions/inference
python setup.py build_ext --inplace
```

## 5. Git 不会自动带走什么

以下内容被 `.gitignore` 排除或只有少量索引文件被跟踪，必须另行复制：

| 内容 | 当前位置 | 是否必须 |
|---|---|---|
| 数据 | `/workspace/Data` | 评测/训练时按数据集复制 |
| 模型权重 | `/workspace/AIForCompression/checkpoints`，约 24 GB | 运行对应神经网络模型时必须 |
| 当前完整结果 | `unified_results/`，约 87 MB | 只保留 Git 中正式单文件报告时可不复制 |
| 历史结果备份 | `unified_results_backup_20260811/`，约 135 MB | 可选，本地备份，Git 中没有 |
| 训练日志 | `logs/`、`wandb/` | 继续分析训练过程或续接 W&B 时可选 |
| 临时/编译文件 | `tmp/`、cache、`models/**/build` | 不复制，重新生成 |

`normalization/`、正式协议、脚本和文档已由 Git 跟踪，正常克隆即可获得。

## 6. 复制数据、权重和结果

推荐在新机器上使用 `rsync` 从旧机器拉取。将 `OLD_HOST` 替换为 SSH 主机名；末尾的 `/` 表示复制目录内容：

```bash
mkdir -p /workspace/AIForCompression/checkpoints /workspace/Data

rsync -aH --info=progress2 \
  OLD_HOST:/workspace/AIForCompression/checkpoints/ \
  /workspace/AIForCompression/checkpoints/

rsync -aH --info=progress2 \
  OLD_HOST:/workspace/Data/ \
  /workspace/Data/

rsync -aH --info=progress2 \
  OLD_HOST:/workspace/AIForCompression/unified_results/ \
  /workspace/AIForCompression/unified_results/
```

继续训练时，再按需要复制日志和历史备份：

```bash
rsync -aH --info=progress2 \
  OLD_HOST:/workspace/AIForCompression/wandb/ \
  /workspace/AIForCompression/wandb/

rsync -aH --info=progress2 \
  OLD_HOST:/workspace/AIForCompression/unified_results_backup_20260811/ \
  /workspace/AIForCompression/unified_results_backup_20260811/
```

数据量很大时，不要默认复制整个 `/workspace/Data`。先根据 `benchmark_protocols/objective_v1.json` 和 `docs/benchmark_reproduction_manifest.md` 选择需要的数据集。

主要数据位置如下：

|---|---|

| UVG | `/workspace/Data/UVG_Twilight_1080p` |
| E3SM | `/workspace/Data/E3SM/caesar_processed/e3sm_5vars_paperlike240_first800_caesar.npz` |
| ERA5 测试 | `/workspace/Data/ERA5/finetune_processed/era5_test.npy` |
| ERA5 训练 | `/workspace/Data/ERA5/hourly_center512_20240301_90d/`、`/workspace/Data/ERA5/finetune_processed/` |

| Tomo | `/workspace/Data/tomo_00001.h5` |

Hurricane、NYX 和 Sentinel-2 的精确文件、样本 ID、crop 与 checksum 以复现清单为准。

## 7. Checkpoint 迁移建议

最稳妥的做法是完整复制 `checkpoints/`。若只迁移最终 ERA5/CAESAR 工作，至少保留：

```text
checkpoints/caesar/caesar_v.pt
checkpoints/caesar/caesar_d.pt
checkpoints/caesar_era5_v_decoder_quality_100k/from_lowrate_lr3em4.pt
checkpoints/caesar_era5_d_complete_candidates/lam3em4_decoder100k_stage2_overlap5000.pt
```

正式全模型评测还需要 DCAE、LIC-HPCM、DCMVC 和 DCVC-RT 的对应权重。完整文件名与每个数据集实际使用的配置见 `docs/benchmark_reproduction_manifest.md`。

可用 SHA256 检查关键最终权重是否损坏：

```bash
sha256sum \
  checkpoints/caesar/caesar_v.pt \
  checkpoints/caesar/caesar_d.pt \
  checkpoints/caesar_era5_v_decoder_quality_100k/from_lowrate_lr3em4.pt \
  checkpoints/caesar_era5_d_complete_candidates/lam3em4_decoder100k_stage2_overlap5000.pt
```

## 8. 如果新机器路径不同

保持原目录布局最省事。如果必须改路径，先找出绝对路径引用：

```bash
rg -n '/workspace/AIForCompression|/workspace/Data|/data/run01' \
  scripts compression_pipeline benchmark_protocols models
```

然后优先修改命令行参数、协议副本或 adapter 配置，不要直接改正式结果中的 provenance。路径改变不应改变样本 ID、裁剪范围、normalization、checkpoint 或 checksum。

## 9. 迁移后的验收

依次执行以下检查：

```bash
cd /workspace/AIForCompression
source .venv/bin/activate

git submodule status --recursive
python scripts/run_objective_benchmark.py --help

pytest -q \
  tests/test_objective_data.py \
  tests/test_objective_stacking.py \
  tests/test_audit_objective_benchmark.py

python scripts/audit_objective_benchmark.py \
  unified_results/objective_all_to_all_v1 \
  --strict
```

最后用浏览器打开 `unified_results/objective_all_to_all_v1/index.html`。如果严格审计通过、GPU import 正常、关键权重 checksum 一致，代码与正式结果迁移即完成；再对计划使用的一个数据集做 smoke test，即可确认数据路径和模型扩展也正常。

## 10. 不建议迁移的内容

- 已清理或废弃的旧结果；需要留档的内容已经放在 `unified_results_backup_20260811/`。
- GraphComp 历史结果；它不属于当前 objective-v1 正式排名。
- `tmp/`、Python cache、下载 cache、旧机器的 CUDA build 目录。
- 可从 checkpoint 和正式 JSON 重新生成的中间图表。

迁移完成后，先不要删除旧机器数据。至少完成一次 checksum、严格审计和目标模型 smoke test，再把旧机器降级为备份。

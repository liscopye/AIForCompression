# 环境激活与测试启动

本文只回答两件事：如何进入当前可运行环境，以及如何从最小检查逐步启动正式测试。完整的数据选择、控制点和指标协议见 `benchmark_reproduction_manifest.md`。

## 1. 当前机器启动方式

每次打开新终端先执行：

```bash
source /workspace/ai4cp/bin/activate
cd /workspace/AIForCompression
```

确认 Python、GPU、核心依赖和模型子模块：

```bash
which python
python --version
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
nvidia-smi
git submodule status --recursive
```

预期使用 `/workspace/ai4cp/bin/python`，`torch.cuda.is_available()` 为 `True`。若模型子模块行首为 `-`，执行：

```bash
git submodule update --init --recursive
```

数据位于 `/workspace/Data`，权重位于仓库的 `checkpoints/`。环境存在不代表数据和权重完整；缺少资产时根据报错对照 `Data数据集.md` 和 `benchmark_reproduction_manifest.md`。

## 2. 最小健康检查

先运行不需要完整模型矩阵的框架回归测试：

```bash
pytest -q tests/test_compression_pipeline.py
```

查看两个主要入口是否能加载：

```bash
python scripts/run_dataset_compression.py --help
python scripts/run_objective_benchmark.py --help
```

开发阶段可用 Kodak 单样本、单模型 smoke test：

```bash
python scripts/run_dataset_compression.py \
  --dataset kodak \
  --data_root /workspace/Data/Kodac \
  --output_dir /tmp/aifc_kodak_smoke \
  --models DCAE \
  --max_model_jobs 1 \
  --max_samples 1 \
  --gpu 0
```

`/tmp/aifc_kodak_smoke` 是临时输出，不进入正式 Objective-v1 结果。

## 3. 普通开发测试

通用入口适合 adapter、模型 wrapper 和少量样本调试：

```bash
python scripts/run_dataset_compression.py \
  --dataset <dataset> \
  --data_root <data_path> \
  --output_dir /tmp/<run_name> \
  --models <model...> \
  --max_samples 1 \
  --gpu 0
```

例如 Turb-Rot 的单模型检查：

```bash
python scripts/run_dataset_compression.py \
  --dataset turb_rot_npz \
  --data_root /workspace/Data/Turb_Rot_testset.npz \
  --output_dir /tmp/aifc_turb_rot_smoke \
  --models caesar_v \
  --max_samples 8 \
  --max_channels 1 \
  --gpu 0
```

开发 smoke 的结果不能直接与正式结果混合，因为样本数、控制点和计时次数可能不同。

## 4. Objective-v1 正式测试

正式测试使用冻结的 canonical 输入。已有输入 manifest 位于：

```text
unified_results/objective_all_to_all_v1/<dataset>/samples.json
unified_results/objective_all_to_all_v1/<dataset>/normalization.json
```

如需从原始数据重新准备某个数据集：

```bash
python scripts/prepare_objective_inputs.py \
  --dataset <dataset_id> \
  --output-root unified_results/objective_inputs_v1
```

图像模型、科学模型、CAESAR 和传统 codec 使用：

```bash
python scripts/run_objective_benchmark.py \
  --dataset <dataset_id> \
  --gpu 0 \
  --input-root unified_results/objective_all_to_all_v1 \
  --output-root unified_results/objective_runs_staging/<run_name> \
  --models <model...> \
  --warmups 2 \
  --repeats 5
```

示例：测试 Kodak 的两个帧内视频模型：

```bash
python scripts/run_objective_benchmark.py \
  --dataset kodak \
  --gpu 0 \
  --input-root unified_results/objective_all_to_all_v1 \
  --output-root unified_results/objective_runs_staging/kodak_intra \
  --models DCMVC-I DCVC-RT-I \
  --warmups 2 \
  --repeats 5
```

科学数据的 CAESAR/cuSZ error bound 和 nvJPEG2000 target PSNR 必须使用正式清单中的数据集专用值，不应直接依赖脚本默认值。

## 5. UVG 视频测试

UVG 的两类测试使用不同入口：

- `DCMVC-I`、`DCVC-RT-I` 逐帧帧内基线：使用 `run_objective_benchmark.py`。
- `DCMVC-IP`、`DCVC-RT-IP` 完整 I+P GOP：使用 `run_objective_video.py`。

运行 I+P 测试：

```bash
python scripts/run_objective_video.py \
  --root unified_results/objective_all_to_all_v1 \
  --gpu 0 \
  --models dcmvc dcvc \
  --warmups 2 \
  --repeats 5
```

该命令会写入 `<root>/uvg_twilight_1080p/video_summary.json`。不要在两个并发进程中写同一个结果文件；不同 GPU 并行测试时必须给每个进程独立输出目录，完成后再合并。

## 6. 结果放置与查看

目录职责：

```text
unified_results/objective_runs_staging/   # 正在运行、尚未审计
unified_results/objective_runs/<dataset>/ # 已保留的运行来源
unified_results/objective_all_to_all_v1/  # 正式筛选汇总和最终页面
```

新测试先写入 staging。验证完成后，将来源放入：

```text
unified_results/objective_runs/<dataset>/<run_name>/
```

正式结果页：

```text
unified_results/objective_all_to_all_v1/index.html
```

重新审计和生成页面：

```bash
python scripts/audit_objective_benchmark.py \
  unified_results/objective_all_to_all_v1 \
  --strict

python scripts/analyze_objective_benchmark.py \
  --root unified_results/objective_all_to_all_v1
```

不要直接把 smoke、失败行或未完成控制点复制进正式目录。正式合并应使用 `build_objective_all_to_all.py`，并在替换正式结果前对临时构建目录执行 `--strict` 审计。

## 7. 常见问题

### CUDA 不可用

确认已经激活 `/workspace/ai4cp`，再检查 `nvidia-smi` 和 `CUDA_VISIBLE_DEVICES`。本机可显式传 `--gpu 0`；Slurm 作业中不要覆盖调度器分配的 `CUDA_VISIBLE_DEVICES`。

### 找不到 checkpoint

检查 `checkpoints/` 下对应模型目录。`tests/test_model_registry.py` 依赖部分历史权重，缺少 LIC-TCM 历史 checkpoint 时不作为当前精简仓库的基础健康检查。

### 显存不足

先只运行一个模型和一个控制点。开发入口可降低 `--max_samples`、`--max_channels` 或 batch；正式结果不得通过减少协议样本来规避显存问题。

### 结果目录已有内容

避免随意使用 `--force`。它可能清除对应模型的旧行；应优先创建新的 staging run，验证后再合并。

## 8. 新机器

新机器先按仓库根目录 `README.md` 的“安装与基本使用”安装基础环境，再根据 `benchmark_reproduction_manifest.md` 配置数据、checkpoint 和外部 codec。完成迁移后，按本文第 1、2 节执行环境和 smoke 验收。
